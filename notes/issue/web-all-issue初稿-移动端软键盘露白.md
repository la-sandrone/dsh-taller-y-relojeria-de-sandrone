# [Bug] 移动端软键盘弹出后 composer 下方露出空白：`_boot` 根容器高度不跟随 visualViewport

> 初稿（2026-10-27）。发之前请自己过一遍，尤其是「推测」那一节——那部分我没在真机上验证完。

## 环境

| 项 | 值 |
|---|---|
| DSH | 0.2.1-rc.2 |
| `@linxin666/dsh-web-all` | 0.4.8 |
| 浏览器 | Firefox 157.0（Android 16） |
| 访问路径 | 手机 → dsh-market 固定中继 → quick tunnel → `127.0.0.1:9007` |

## 现象

远程 Web UI 竖屏使用时，软键盘弹出/收起**数次之后**，composer 下方露出一块页面背景（壁纸直露），页面看起来没有铺满视口。

刷新可暂时恢复，但这条链路上刷新成本很高（每次要走公网隧道，且偶发 1033）。**隐私窗口下症状完全一致**，已排除浏览器缓存。

第 4 张是关键：探针是 `position:fixed; top:0`，它会被挤出可视区，说明**页面正在被浏览器滚动**（因为根容器比可视区高 280px）。

## 复现

1. 手机通过配对链接进入远程 Web UI（竖屏）
2. 点输入框唤出软键盘，打几个字，收起
3. 重复 3–5 次
4. composer 下方空白逐渐出现并稳定存在

## 证据

### 1. `visualViewport` 工作正常

临时探针读取 `visualViewport.height` / `innerHeight` / `#root.firstElementChild` 高度：

| 时刻 | VV | IH | 根容器高度 |
|---|---|---|---|
| 无键盘 | 636 | 636 | 636 |
| 键盘弹出 | **356** | 636 | **636** |

⇒ `vv.height` 是可靠信号，但根容器没有跟随它。

### 2. 适配层的关键规则从未生效

`lib/client.js` 注入的规则：

```js
"[class*=\"_frame\"]:has([class*=\"_centerCol\"]){width:100%;height:100dvh}"
```

而 `_centerCol` 在 DSH 0.2.1-rc.2 的客户端构建产物里**一处都不存在**：

```
$ rg -l 'centerCol' apps/web/dist
（无输出）
```

⇒ 这条规则自上线起就是永假的，根容器从来没拿到过 `100dvh`。

### 3. 真实根容器类名不是 `_frame`

实测 `#root.firstElementChild` 的 className：

```
_boot_u7vgf_3
```

⇒ 适配层按 `_frame` 定位，命中的是内部另一个元素，不是根容器。

### 4. 同类选择器在 0.2.1-rc.2 上大面积对不上

在 `apps/web/dist` 里逐个验证：

```
_bubble ✓   _input ✓   _scroll ✓   _frame_1hfzl_1 ✓
centerCol ✗   _composer ✗   _composerSeat ✗
_railFish ✗   _newSession ✗   _panelIcon ✗   _scrollBody ✗
```

（后者正是移动适配层「44px 触控目标 / 键盘安全区内边距 / 紧凑字号」的锚点）

## 推测（未验证）

`html` / `body` / `#root` 三层在 `packages/client/web/src/base.css:6` 里都是 `height:100%`；键盘弹出时三层仍然是 636。

⇒ 只把 `_boot` 压到 356 可能不够，`#root` 底部那 280px 仍会露出，**需要整条链一起覆盖**。
这一条我没验证完（真机上反复试验的成本太高）。

## 建议

1. **`dvh` 不跟软键盘**，只有 `visualViewport.height` 会变。建议用 `visualViewport` 驱动一个 CSS 变量，而不是直接写 `100dvh`。
2. **选择器以实际类名为准**：根容器是 `_boot_*`，不是 `_frame`；`_centerCol` / `_composer` / `_railFish` / `_scrollBody` 在 0.2.1-rc.2 上已不存在。
3. **高度链要整条覆盖**：`html, body, #root, [class^="_boot_"]` 一起跟变量，单独改一层无效。
4. **不要依赖 CSS Modules 生成名**。

   `[class*="_centerCol"]` 这类选择器由构建决定、随上游重构变化，而且**匹配失败时零信号**——浏览器只是不应用这条规则，不报错、不警告，开发者和用户都只能看到"页面有点怪"。

   这次就是：DSH 0.2.1-rc.2 把类名改掉之后，适配层的核心规则**静默失效**，一直没被发现。

   建议改用 `data-*` 属性、`#root > *` 这类结构锚点；或者在适配层启动时把关键选择器挨个 `querySelector` 一遍，匹配数为 0 就打一行 console 警告。**让"对不上"变成可见的失败**，比事后排查便宜得多。

## 附：0.4.3 – 0.4.10 均未涉及

逐版本看了 release notes，`remote-web-ui` 的改动全部集中在设备 / 网络 / 中继 / 设置保存：

| 版本 | remote-web-ui 的改动 |
|---|---|
| 0.4.8 | 转发请求不算回环、绑定地址、隧道子进程回收 |
| 0.4.9 | 设备命名合并、局域网可达性、回环判定分层、请求头转发、中继租约 |
| 0.4.10 | 无（改动集中在 `remote-bridge` 的 `ui.v1` 与 settings 重构） |
| 0.4.3 – 0.4.7 | 移动抽屉保持展开、lan-bind 的 YAML 写入器、设置串行化 |

**没有任何一版碰过移动端的视口 / 键盘。**

所以升到 0.4.10 预期不解决此问题（且它要求 DSH ≥ 0.2.1-rc.3，升级链更长）。
