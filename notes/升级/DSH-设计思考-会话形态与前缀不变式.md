# 技术思考：会话形态必须落盘（前缀不变式）

文件名: 用户笔记/升级/DSH-设计思考-会话形态与前缀不变式.md
摘要: 一次真实的「会话永久 400」事故，本质不是 bug 而是**设计缺口**：DSH 在请求时用**当前部署配置**解析工具面，却拿它去解释**旧会话**的历史 ⇒ 换执行器即成整体替换，增量协议表达不了。借 NT 的升级经验给出原则：**凡进入请求前缀的东西，必须在会话出生时盖章**。
状态: 思考稿（结论可用，**不是**待办方案；若上游改设计，本文件的判据仍成立）

---

## 一、事故一句话

旧会话（原生 132 个工具）在 0.2.2 上重开，而 0.2.2 打开了 PTC（面只剩 `run_code`）⇒
loop 追加 `request/header{reason:'change'|'resume'}` + `tool-removal`/`tool-addition` ⇒
投影把基线删光、剩下的工具作为 deferred addition ⇒ **整份声明集全延期** ⇒ 服务端 400 ⇒ 该会话此后每轮都失败。

细节与三份 `request_id` 见 `补丁/defer全延期兜底/defer全延期兜底.md`；逐轮取证见 `升级/DSH升级-0.2.2-rc.1-调查与方案.md` §11.8–§11.16。

## 二、定性：不是 bug，是**用当下配置解释历史数据**

`SESSION_FORMAT_VERSION`（=4）管的是**数据格式**，这部分 DSH 做得对：0.2.1 的会话在 0.2.2 上照样能读。
但「**这个会话该用哪张工具面/哪个执行器**」既没有版本化，也没有落盘 —— 每次 resume 现算，算出来的必然是**今天的答案**。

用当下环境状态去解释历史数据，是升级兼容性里最经典的一类错，NT 时代就有名字：**ambient authority**。

## 三、NT 为什么「升级稳如老狗」

| 机制 | 具体形态 | 对应到 DSH 的缺口 |
|---|---|---|
| **并存不覆盖** | WinSxS：同一组件多版本并列，按完整版本引用 | 执行器只有「当前生效」一种，没有「会话级的那个」 |
| **接口永不改义** | COM 接口不可变；换语义 = 新接口 + 新 IID，靠 `QueryInterface` 协商 | 模型能力有协商（`in-history`/`addition-only`），**执行器能力没有** |
| **数据自带来历** | 格式带版本戳，升级用迁移表搬运 | 会话带了工具史，**但没带「该用哪种执行器」** |
| **兼容层显式** | AppCompat shim 按应用登记、可查可撤 | 我们的 14 行投影兜底就是 shim —— 它该被登记（已在 `补丁/`），而不是藏在代码里 |

一句话：**旧东西按它当时的规则继续跑；新规则只作用于新东西；交界处必须有显式迁移。**

## 四、落点（如果按这条原则改 DSH）

```ts
// SessionHeader 增加一个字段：会话出生时盖章
toolFace?: 'native' | 'ptc'
```

- 新会话：按当前配置盖章；
- resume：**读章**，不看当前配置；
- 老会话（无章）：按 legacy `native` 解释，并**主动开一个新声明系列**（认一次缓存损失），此后固定；
- 真要换面：那是**显式迁移动作**（有名字、可回滚、按会话批量），不是「改个 cordis 配置下次开机全体生效」。

配套：`baseline ∩ active = ∅`（或收缩过半）应当**由 loop 主动开新 series**，因为那时增量表达已不可能 —— 现在这个判断只存在于「同名定义变了 / resume / 压缩边界」三处。

## 五、可推广的原则：**前缀不变式**

> **凡进入请求前缀（system + tools + 早期消息）的东西，必须在会话出生时盖章；
> 凡每次现算的东西，必须保证它不进入前缀。**

违反这条的后果不是「慢」，是**同一个会话在不同时间被解释成两套语义**：投影可非法、缓存必失效、行为不可复现。

### 五之二、本工作区原本的形态：**一切归 ID，前缀写入即封存**

上面「盖章」只是实现手段之一。本工作区设计时立的规矩更硬，也更简单：

> **① 一切归会话 ID。**
> **② 凡写进前缀的内容，写进去之后就永不改变。**
> **③ 万事转进开新对话** —— 需要换面的，是**新会话**的事，不是**迁移老会话**的事。

这三条一旦成立，本文第二～四节那一整类问题**在结构上就不存在**：
没有中途换面、没有 series 重开、没有 `all-deferred`、不需要 shim，也不需要「盖章」这个字段 ——
因为历史前缀根本不参与重新计算，它只是**被原样续写**。

**但有个前提必须说清**（否则「永不改变」是句空话）：

> 前缀不变式要求「**当时那张面仍然可重建**」。

这正是 NT 的 WinSxS 在做的事：并存，才能维持旧引用。放到 DSH 上，这件事**今天就可做到**，因为

- **PTC 是「呈现方式」，不是「工具是否存在」**：工具注册表里原生工具一直都在，`run_code` 只是另一种呈现；
- 所以老会话完全可以继续按 native 呈现、新会话按 PTC 呈现，两者并存 —— 谁也不必改写谁。

⇒ 真正缺的不是能力，而是**一条「按会话读面、而不是按当前配置算面」的解析顺序**。
这也是为什么本文说它是设计缺口而非 bug：能力齐备，契约没立。

### 五之三、由此推出的操作纪律（不需要任何补丁）

| 场景 | 该怎么做 | 不该怎么做 |
|---|---|---|
| 升级/换执行器 | 老会话按**原面**续跑；要新面就**开新对话** | 让升级后的默认配置去重新解释老会话 |
| 老面已不可重建（插件被删、工具改名） | **明确拒绝或降为只读**，并说清缺什么 | 悄悄换成能跑的新面（即「用当下解释历史」） |
| System Prompt / 技能目录变了 | 同上：老会话不变，新对话用新的 | 在会话中途注入新提示词 |

**我们的 14 行补丁在这套规矩下永远不会被触发** —— 它只为「已经被旧配置改写坏」的历史会话保命。
换句话说：补丁存在本身就是「契约没立」的证据。

DSH 里已经做对的一个反例可以对照：**沙盒 mode 是会话投影**（`sandboxModeProjection`）——
权限模式确实按会话记住并恢复，所以「换 mode」不会把老会话解释坏。工具面缺的正是这一步。

## 六、预测：这套坑以后还会撞（判据而非清单）

只要满足两个条件，就是同一类坑：**① 该面影响前缀；② 它在请求时从当前配置解析。**

| 面 | 现在怎么解析 | 风险 |
|---|---|---|
| 工具面 / 执行器 | 请求时按当前配置 | **已炸**（本文） |
| System Prompt（preset 组成） | resume 时按当前 preset 组成 | preset 改动即**整段前缀失效**，且老会话被新提示词语义覆盖 |
| 插件/MCP 工具增减 | 注册表实时 | 走的是同一套 addition/removal ⇒ 同类非法态（`all-deferred`） |
| 权限 mode | **会话投影，已落盘** | 做对了，可作为模板 |
| 压缩策略 / 上下文窗口 | 请求时按模型元数据 | 影响的是历史裁剪点，不直接破前缀，但会让「同一会话不同轮」不可复现 |
| 技能目录 | 作为消息注入 | 注入内容变化 = 前缀中段变化，缓存按段失效 |

**升级时的检查项（写给自己）**：每次升级前，把「本次改了什么面」逐个过一遍第 ① ② 两条判据；命中就问一句「**这个面会话语义是怎么固定的**」，答不上来就是下一个 400。

## 七、结尾：PTC 与缓存策略其实是同一件事

PTC 把工具面压成常量 1，让**前缀彻底不动**，所有多样性挪进消息流里的代码 —— 这不是与缓存策略冲突，**它就是缓存策略**。
所以事故的根不在 PTC，在「换面没有被建模成系列边界」。等所有会话都是 PTC 出生的，这个坑自然不再触发；
但**只要还有一次换面，就还会撞** —— 除非把「面」按第四、五节落盘。
