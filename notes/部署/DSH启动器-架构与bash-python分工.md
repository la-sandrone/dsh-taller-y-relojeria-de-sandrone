## 〇、一句话

**bash 只做一件它能做好的事**：运行一个临时生成的 `.sh` —— 里面 `source` 好环境，
最后 `exec` 真身替换自己。**其余逻辑一律 python。**

这条不是审美，是被下面那条陷阱逼出来的。

## 一、bash 干不了的那件事：`set -euo pipefail` 下的**静默自杀**

### 复现（最小）

```bash
bash -c 'set -euo pipefail
         p="$(sed -n "s/x/y/p" /不存在的文件 2>/dev/null | head -1)"
         echo "这行永远不会执行"'
echo "退出码=$?"      # → 2，且上面那行确实没打印
```

零输出、零报错、退出码 2。**看起来像「命令什么都没干」。**

### 机制（三步，缺一不可）

1. `sed` 读不到文件 → 返回 **2**
2. `set -o pipefail` → 管道 `sed | head` 的整体状态取**最右非零** = **2**
   （没有 pipefail 时 `head` 成功会把它盖成 0）
3. `p="$(...)"` 的赋值**继承**该状态 → `set -e` → **shell 直接退出**
4. 而 `2>/dev/null` 把 sed 的报错也吞了 ⟹ **全程无声**

### 2026-10-08 的实际伤情

`start-web.sh` 的 `--try V --stop` / `--version V --stop` 在**没有记录文件**时：

- 期望：报错说「找不到记录」
- 实际：**无声退出 2**，用户只看到"什么都没发生"

排查时 `bash -x` 的痕迹停在 `+ p=` 就没有下文了 —— 因为 `set -e` 是在**赋值语句**上退出的，
连下一个 `if` 都没来得及 trace。

### 修法

```bash
rec_field() {
  local f="$INSTANCE_DIR/$1.json"
  [ -f "$f" ] || { printf ''; return 0; }   # ← 先判存在，缺则回空串且**返回 0**
  sed -n '...' "$f" 2>/dev/null | head -1 || true
}
```

**两条纪律**：
- 任何可能读不到文件的取值函数，**自己兜住并把状态归零**——不要让 `set -e` 去猜
- 调用方**不需要**（也不该）写 `|| true` 来救——那会把真正的错误一起吞掉

> **教训一句话**：`set -e` 是「宁可炸也不静默降级」的工具，但它和
> `pipefail` + 命令替换 + 重定向吞 stderr 组合起来，会变成**恰恰相反**的东西
> ——最彻底的静默。这是本项目「以静默降级为耻」那条准则的一个反例形态：
> **静默的不是降级，是自杀。**

## 二、分工纪律（四条必守）

### 先定边界：bash 的能力上限（用户 2026-10-08 定）

> bash 只适合干个
> ```
> export HTTPS_PROXY=XXXX
> source ~/ai-services/bin/activate
> exec XXXXXX
> ```
> 这样的简单活，要不然 **bash 比 cmd 还生猛**。

**判据**：bash 合适的是**「设环境 → 起进程 → 交出自己的身份（`exec`）」**这条直线。

一旦出现下面任何一样，就已经超出它的能力上限：

| 出现的信号 | 为什么 bash 撑不住 |
|---|---|
| **状态机**（前台/后台、启动中/已停） | 没有数据结构，只能靠变量名约定 + `case` 串联；分支一多就没人能读懂 |
| **条件分支树** | 每层嵌套都要重新推演引号与展开；`[ ]` 与 `[[ ]]` 语义还不一致 |
| **跨步骤的失败语义** | 只有"退出码"一个信息位；而 `set -e` 又和管道、子 shell 互相干扰（§一 那个静默自杀陷阱正是它） |
| **自己的数据结构**（记录、目标解析） | 只能靠 jq/sed/awk 外挂 + 字符串拼接 —— 用文本模拟结构体 |
| **需要单测的逻辑** | 没有单测生态；`bash -n` 只查语法，shellcheck 还不一定装了 |

`start-web.sh`（543 行）现在恰好压在这条线上：实例所有权记录、严格的停止目标解析、
前台/后台两套退出语义、`set -euo pipefail` 下的隐式自杀……

**这些都是"程序"的活，不是"设置环境"的活。**

⟹ **不要试图把 bash 修得更好，要把它搬走**（§四）。凡待办里写成"改 `start-web.sh` 某处"的项，
先问一句：**这是不是又一次在给一个超龄的语言续命？**

来源：用户既有实践，记载于 `<venv盘>\my-program\mineru_batch.py`（WSL 侧
`<挂载e>:/venv-cuda/my-program/mineru_batch.py`，2001 行，python 持逻辑 + 生成 bash）。

```
① Python 持全部逻辑，用 L.append(...) 逐行拼出 bash 脚本 → 落 /tmp（可复查、可手动重跑）
② 执行用  bash -l <脚本>，**绝不用 -c**
     理由：-c "bash xxx.sh" 的字符串要穿过 传参链 → 引号会被重写（v4.4 的引号破坏教训）
③ 生成的 bash 必须过**引号上下文安全检查**
     理由：python 造 bash 时，引号是头号杀手（mineru_batch.py 里有一整个检查函数）
④ Ctrl+C 与子进程抢信号是**已知地雷** ⟹ python 侧必须用
     signal.signal(SIGINT, SIG_IGN) 包住 wait
     否则抢信号会把子进程变孤儿（mineru_batch.py 为此留了 PLAN-B：
     启动后立即 os._exit(0)，让子进程自己活）
```

`exec` 的语义归属：**在生成的那个脚本里** `exec` 真身 —— 进程替换发生在 bash 里，
python 只负责把它拉起来、等它、收尾。

## 三、start-web.sh 现状（2026-10-08 已修，未迁移）

**仍是 543 行 bash。** 本次只修了缺陷，没有改架构。

### 修掉的缺陷

`--try` 的端口由 `free_port()` **自动找空闲**挑；事后要停它时它**正在监听**，
`free_port()` 必然算出**另一个**端口 ⟹

- `--try V --stop` 停不掉任何东西
- 更糟：会把**碰巧占用那个端口的无关进程**当目标杀掉

修法：**实例所有权记录**（见 §五）+ 目标解析严格优先级 + 查不到就报错。

### 2026-10-08 修 bug 过程中又抓到两个自己的 bug

| bug | 形态 | 修法 |
|---|---|---|
| 静默退出 | §一 那条 | 取值函数自己兜住 |
| **删错文件** | `forget_instance` 用全局 `$DSH_VERSION`，而 `--version V --stop` 时被停实例是 `$sel`（≠ 派生版本）⟹ 删了 v0.1.7 的记录、留下 v0.2.0 的，**提示却打「已清除」** | 函数接受版本参数；并把 `$sel` 提到 `do_stop` 开头；**加复验**（清完文件仍在则报错返回 1） |

> 第二个 bug 的教训值得单列：**提示语不能当证据**。
> 「已清除」是打印的字面量，不是对结果的检查。现在的写法是
> **操作完真的去 `[ -f ]` 看一眼**，不一致就报错。

### 目标架构

```

## 五、多实例管理语义：「谁的儿子谁抱回家」

### 为什么需要

无状态启动器（选端口 → 起 → 印 URL → 忘掉）里，**「我起过谁」无从查起**。
于是既停不掉，也无法判断某个实例是不是自己起的。

### 所有权记录

启动时落 `_scratch/instances/<版本>.json`：

```json
{"version":"v0.2.0-rc.2","home":"dsh-domus-0.2.0-rc.2","port":9009,"pid":1772345,
 "mode":"background","launcher_pid":1770575,"started_at":"2026-10-08T07:10:37+08:00"}
```

前台/后台都落。前台正常退出时删；后台由 `--stop` 删。

### 目标解析（`--stop` / `--status` 共用）—— **严格优先级，绝不猜**

```
1) --port N               → 按端口。永远可用，不做任何推导。
2) --version V / --try V  → 查记录拿端口；**查不到即报错退出（码 4）**，
                            绝不退回落 free_port()（那正是误杀无关进程的来源）
3) 都不给                  → 主实例（DSH_VERSION → MAIN_PORT）
```

### ★ 两种模式的停止方式**语义不同**（用户 2026-10-08 明确要求保住前者）

| 模式 | 进程关系 | 停止方式 | 设计理由 |
|---|---|---|---|
| **前台**（默认） | 实例与 launcher **同前台进程组** | **Ctrl+C** —— SIGINT 直达 host | 用户要求：「前台用 Ctrl+C 就能把所有人带走」 |
| **后台** `--background` | `setsid` → **自己的会话** | 只能 `--stop --version V` / `--port N` | 脱离终端后没有"前台"可回 |

**因此：**
- 前台分支**不用 setsid**、**不提供 `--stop`** —— 那两条路径会打架
- 后台分支**必须** setsid（实测生效：实例 PGID=SID=自身，launcher 退出后不留孤儿）
- 后台模式的 `--stop` **连带收掉 launcher 包装进程**；前台**不**这么做
  （那个进程正是持终端、转发 SIGINT 的角色）

前台收尾的实现细节（不要动）：

```bash
trap '' INT                          # 脚本自身免疫 SIGINT，好让它能打完收尾
pnpm dsh web ... 2>&1 | tee -a "$LOG"   # 同前台进程组 → SIGINT 直达 node 与 tee
rc="${PIPESTATUS[0]}"                # 必须紧跟同一命令：单独一行会重置 PIPESTATUS
trap - INT
```

## 六、操作安全性：**改一个正在运行的脚本不会伤到它**

改 `start-web.sh` 时它在跑（现役 launcher 是执行该文件的 bash），怕偏移错位。

**结论：安全，前提是编辑器「替换」而非「原地改写」。** 实测证据：

```
现役 launcher 的 fd 255 → start-web.sh (deleted)     ← 旧 inode 已被 unlink
  fd255 inode=1835010  size=20369   pos=20027        ← 它继续读【改动前】的内容
新文件 inode=1703940  size=27560                     ← 完全另一个 inode
```

bash **持有脚本 fd**，`rename` 只改目录项；旧 inode 因 fd 而存活，内容不变。
⟹ 正在跑的实例**不受影响**。

**待查的一点**：bash 对脚本是按块读的，`pos` 只表示读到哪。本次剩余仅 342 字节，
大概率已在缓冲区里。若将来需要**原地改写**（同 inode）正在运行的脚本，
**必须**先确认剩余量 < 缓冲区大小 —— 否则会从偏移处读到错位内容。

## 七、同类陷阱的全面审计（2026-10-08 已做，结果：只有一处）

把 §一 那条陷阱的**候选面**定成：「命令替换里带管道」+「被 `set -e` 管」。
全脚本扫描结果：

| 位置 | 形态 | 是否已兜 |
|---|---|---|
| L125 `PORT="$(free_port)"` | 无管道 | ✅ 有显式 `\|\| die` |
| L131 `LAUNCHER_LABEL="$([ ] && echo \|\| echo)"` | `&&/\|\|` 内建 | ✅ echo 恒成功 |
| L204 `all="$(ss -ltnp 2>/dev/null \|\| true)"` | 吞 stderr | ✅ `\|\| true` |
| L216 `cmd="$(tr ... 2>/dev/null \|\| true)"` | 吞 stderr | ✅ `\|\| true` |
| L228 `url="$(grep ... 2>/dev/null \| tail -1 \|\| true)"` | **有管道** | ✅ `\|\| true` |
| L251 `n="$(tr ... \| grep -cE ... \|\| true)"` | **有管道** | ✅ `\|\| true` |
| L375 `LEAK="$(grep -rlE ... \| grep -v ... \|\| true)"` | **有管道 + 多行** | ✅ `\|\| true` |
| ~~`rec_field` / `rec_mode`~~ | **有管道 + 吞 stderr + 无兜** | ❌ → **本次已修** |

**结论：`rec_field` / `rec_mode` 是全脚本唯一的漏点，已修。其余六处都已自兜。**

> 这条审计值得固化成**写 bash 时的自检项**：
> 凡 `x="$(... | ...)"`，末尾**必须有** `|| true`（或显式 `|| die`）——
> 否则 `pipefail` 会把管道里任何一环的失败升级成整个脚本的**静默退出**。
