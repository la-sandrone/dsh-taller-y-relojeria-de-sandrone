# Windows 冻结版工具清单（2026-10-24 快照）

## 一、为什么需要这份清单

Windows 侧这套东西的好处与代价是一体两面：

- **好处**：冻结版本。Arch 一个 `-Syu` 能把系统带飞，这里不会——
  你不动它，它就永远是装进来那天的样子。
- **代价**：**没有任何东西会替你更新它**。pacman 管不到，Windows Update 管不到，
  应用自己的更新器默认也不一定开。所以「基础工具得手动盯 CVE」这句话是准确的。

清单就是那份"盯"的靶子。没有清单，盯 CVE 等于盲盯。

## 三、捆绑的 OpenSSL 副本（重点）

| 宿主 | 文件 | 版本 | 状态 |
|---|---|---|---|
| PHP 8.5.12 | `php85\libcrypto-3-x64.dll` | **3.5.9**（2026-09） | 当前 LTS 线，随 PHP 发布更新 |
| Python 3.12.10 | `Python312\DLLs\libcrypto-3.dll` | **3.0.16**（2025-02） | 3.0 线已 EOL，**但这条是结构性代价，非疏忽**（见 §四.6） |
| Umi-OCR 2.1.5 | `UmiOCR-data\runtime\libcrypto-1_1.dll` | **1.1.1k**（2021-03） | **1.1.1 线 2023-09 EOL**；1.1.1k 早于 1.1.1l，缺 CVE-2021-3711/3712 等修复 |
| Apache 2.4.68 | `Apache24\bin\libcrypto-3-x64.dll` | 未取（mod_ssl 未加载） | **DLL 存在但从不加载 → 零暴露** |

**关键结论**：所谓"没存 OpenSSL"是错觉。四份里两份在已 EOL 的线上，
而且它们的更新通道**不是 OpenSSL**，是各自宿主应用的下个版本。

但要分清三种「不升」：

- **Python 3.0.16 是结构性代价**：3.12.10 已是最后一个带 Windows 安装包的 3.12，
  再往前只有源码包（见 §四.2）。这条只记录，不催。
- **Umi-OCR 的 1.1.1k 同样是结构性代价**：上游 **v2.1.5（2025-03-25）之后没有新版**
  （GitHub Releases 实测），而本机装的就是 2.1.5 —— 即「已是最新版，而最新版里就是过期 TLS 栈」。
  缓解手段不是升级，是**收窄监听面**：其 HTTP API 实测为 `127.0.0.1:9004`（`server.host=127.0.0.1`），
  局域网/公网都碰不到，实际攻击面 = 本地。

顺带：Windows 自带的 `<C盘>:\Windows\System32\curl.exe` 是 **Schannel** 后端（无 OpenSSL），
所以它不算在内。

## 四、清点过程中的发现

1. **Clash Verge 装了两份 —— 有意为之，不是冗余**：`Clash Verge` 与 `Clash Verge Ninja`
   都是 2.5.2。这类「众所周知的特殊工具」背后是一大堆私有协议，两个 fork 覆盖的协议/内核
   组合不同，留两份是刻意的冗余。**本条不计入清理项**；只需记住：换内核时两份都要想一遍。
   现在跑的是 `clash-verge.exe` + `verge-mihomo.exe`（从进程名看不出是哪一份，需要时按路径查）。
2. **Python 3.12 的冻结有两个独立理由，且都被验证成立**：
   - **轮子敏感**：PyTorch 等二进制轮子对 3.12 的 ABI 极其敏感，minor 一动就得重配整套环境。
   - **更强的一条**：`3.12.10` **就是最后一个带 Windows 安装包的 3.12**——CPython 进入
     security-only 阶段后不再产出 Windows 二进制（实测 `3.12.11`～`3.12.15` 的 FTP 目录里
     只有 `tar.xz` / `tgz` 源码包，`amd64` 安装器一个都没有）。
   ⇒ 所以「OpenSSL 3.0.16 已 EOL」是这条决定的**结构性代价**，不是谁忘了升级。
   可选出路只有三条：迁移到 3.13/3.14（等于重配 PyTorch 世界）、在 Windows 上自编译
   3.12.15（要 MSVC + 一堆依赖）、或者接受。**建议接受并记录**，因为本机 Python 的
   TLS 对端是 PyPI 这类可信源，暴露面小。
3. **`wmic` 已被移除**（LTSC 这版没有）。取文件版本的可用路径只有
   `sigcheck64 -a`（本机已有）或 PowerShell 的 `VersionInfo`。别再照老教程写 `wmic datafile`。
4. **跨平台编译的工具普遍没有版本资源**：aria2、FFmpeg、Pandoc、wimlib、Umi-OCR
   的 PE 里 `File version` 是 n/a，只能跑 `--version`。做自动清点时两条路都要写。
5. **Electron / CEF 类应用（Chatbox / Typora / Quark / JiJiDown）是一个特殊类别**：
   它们的攻击面等于「一份冻结的 Chromium」。app 版本不动，内核就永不动；
   而 Chromium 的 CVE 是按月发的。Typora 1.3.6 明显落后于同类，值得单独核一次上游。
6. **Umi-OCR 的运行时是个 2021 年的化石**（OpenSSL 1.1.1k + 自带 Python），
   且**没有升级出路**：上游最后一个是 v2.1.5（2025-03-25），本机就是这个版本。
   ⇒ 处置方式不是升 TLS，而是**限死监听面**。实测（2026-10-24）：
   `server.enable=true` / `server.host=127.0.0.1` / `server.port=9004`；
   `netstat` 只有 `127.0.0.1:9004`（PID 28584），无 `0.0.0.0`、无 `[::]`。
   **已符合「只听回环」要求，无需改动。**

## 五、下一步（监控设计的输入）

这份清单就是监控脚本的 **inventory**。判定逻辑：

```
对每个工具：
  1. 从上游取「当前最新版本」（GitHub Releases API / 官网 / distro 公告）
  2. 与本表版本比对 → 落后就打标
  3. 若期间有 advisory（CVE / GHSA）命中该工具且 <= 本机版本 → 升级优先级最高
输出：只在"有 CVE 命中"或"落后超过 N 个版本"时说话，否则静默
```

优先级排序（按「会不会吃到不信任输入」）：
**FFmpeg / ImageMagick / 7-Zip / WinRAR / SumatraPDF / LibreOffice**
→ 然后 **Electron 四件套** → 然后 **Node** → 剩下的按闲时处理。

**已定案不动的**：Python（3.12.10 是最后一个带 Windows 安装包的 3.12，见 §四.2）、两份 Clash（刻意冗余，见 §四.1）、Umi-OCR（上游停更于 v2.1.5，且已回环监听，见 §四.6）。这三项在监控里只记录、不报警。

## 六、复现方式（一条条照抄即可）

```bash
# 取某个 exe 的版本（wmic 已不可用）
"<C盘>:\Program Files\SysinternalsSuite\sigcheck64.exe" -accepteula -a "<C盘>:\path\to\app.exe" | grep -i "File version"

# 没有版本资源的工具
aria2c --version | head -1
ffmpeg -version | head -1
pandoc --version | head -1
wimlib-imagex --version | head -1

# 宿主自带的 OpenSSL 版本
python -c "import ssl; print(ssl.OPENSSL_VERSION)"
php -r 'echo OPENSSL_VERSION_TEXT, "\n";'
```
