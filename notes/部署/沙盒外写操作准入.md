# 沙盒外写操作准入

文件名: 用户笔记/部署/沙盒外写操作准入.md
摘要: 工作区（沙盒）以外的文件读写需要什么手续 —— 一次真实事故换来的三条准入，外加「先看当前 policy」的第 0 条（2026-10-09 追加）。
依赖: 无

## 事故（2026-10-09 00:16）

`tools/export-to-sandrone.py --apply` 对 `<挂载e>:/公开发布项目/dsh-sandrone-ui-patches/packages/…`
执行 `shutil.rmtree`，删掉 `lib/`（2 个文件）之后撞上
`OSError: [Errno 30] Read-only file system` 停在中途。

**根因不是脚本**：`/mnt/e` 当时以 `9p … ro` 挂载（约半小时后自己变回 `rw`，期间 probe 探针确认过）。
是**准入流程缺失** —— 动手前没测目标可写；而且把 System Prompt 那句
「bash 汇报工作区外的只读是**假的**」**反向理解**成了「所以能写」。

**抢救**：git 对象完好 ⇒ `git -C <仓库> archive HEAD -o backups/<名>.tar` 全量导出（82 条目，
1.8 MB）；被删文件在 tar 与 git 里都还在。恢复 = 目标可写后重跑导出（脚本会重建整个包目录）。

## 追补（2026-10-09 当晚）：`ro` 有两种来源，`findmnt` 分不出来

同一次发布流程里又撞上「`/mnt/c d e f r` **全部** `9p ro`」。这次先探针一测：**可写**。
挂载选项字符串**一个字符都没变** —— 变的只是会话策略（`workspace-write` → `danger-full-access`）。

⇒ 看到 `ro` **不能**直接判「盘是只读」：

| 可能 | 探针写的结果 |
|---|---|
| **文件系统真的 ro** | 失败 |
| **会话沙盒给的只读视图** | 成功 |

**两种情况唯一的判据都是探针写。** `findmnt` / `mount` / `/proc/mounts` 都看不出来。
（`/etc/wsl.conf` 里没有 `ro`、`/etc/fstab` 也没有 —— 所以看到 `ro` 时，**先去查当前 policy，别去查挂载配置**。）

> 事故记录里还有一处与「盘真 ro」不完全吻合：`shutil.rmtree` 是**先删掉了 `lib/` 才**撞 `Errno 30`
> —— 纯粹的 ro 挂载上第一个 `unlink` 就该失败。这条更贴合「沙盒视图」，但当时没留 probe 的原始输出，
> **不作定论**，只作为「再遇到时优先怀疑哪一边」的提示。

## 第 0 条：先看当前 policy（2026-10-09 追加）

**下面三条**（探针 / 走 MCP / 申请授权）**都是依赖 policy 的**，不是无条件纪律：

| 当前 file policy | approvals | 还需要第 2、3 条吗 | 仍然必须做 |
|---|---|---|---|
| `workspace-write`（默认） | `ask` | **需要** —— 沙盒只放行会话工作区 | **探针测写** |
| `danger-full-access` | `never` | **不需要** —— 沙盒不限制文件操作，也没有审批通道 | **探针测写** |

⇒ **判据是「当前 policy」，不是这份笔记。** policy 已是 `danger-full-access` 时照第 3 条去「申请授权」，
只会**白停一轮**（审批通道本身是关的，申请会被自动拒，`sandbox_permissions` 也不该传）。

**唯一无条件、与 policy 无关的那条，永远是「探针测写」** —— 它测的是文件系统。

## 三条准入（按顺序）

1. **探针测写** —— 任何破坏性写入（`rmtree` / `rm` / `mv` / 覆盖）之前先探：

   ```bash
   probe="<目标目录>/.dsh-write-probe.$$"
   : > "$probe" 2>/dev/null && rm -f "$probe" || echo "不可写 → 停手报告"
   ```

   探针要**紧挨着**真正的写入执行 —— 这台机器上「可写 / 只读」会来回变（**挂载状态**或**会话 policy**，
   两者都变，见上面「追补」）。
2. **沙盒外一律走 MCP 文件工具**（`write_myfilesystem_text_file` 等）—— 它们有自己的
   ALLOWED_ROOTS 权限门，判断归工具、不归模型。
3. **批量操作，或由脚本 / 程序操作沙盒外文件 → 先向用户汇报申请授权**，拿到明确答复再动。

> System Prompt 那条已于 2026-10-09 改成精确表述（正本 `profiles/web/cordis.patch.yml`，5 个 preset）：
> 「沙盒的 bash 汇报工作区以外的目录的只读是**沙盒的故意设计**，需要读写沙盒外面的文件请用
> 我们自己的文件操作MCP，**批量操作沙盒外文件或脚本、程序操作沙盒外文件请直接向用户汇报
> 申请授权**。」

## 顺带：`git` 也算「程序操作沙盒外文件」

`git -C <沙盒外仓库> commit / push` 同样适用第 3 条 —— 提交与推送前确认授权。
（**这条也依赖 policy**：`danger-full-access` + 审批关闭时不需要申请，见「第 0 条」。）

⚠️ 别与 home 仓库的纪律混淆：**home（`dsh-domus-<版本>/`）由启动器在开机前提交**
（见 AGENTS.md「对话记录怎么备份」），实例运行中**不要手工提交** —— 运行中提交可能抓到
半个 zstd 帧，那正是对话迁移那次踩过的「最后一个会话打不开」。
