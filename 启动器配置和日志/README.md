# 启动器配置和日志

`start-web.py` 从**同级**的 `启动器配置和日志/` 读三样东西：

| 需要什么 | 说明 | 本仓是否随附 |
|---|---|---|
| `当前配置.toml` | **人写机读的唯一真相源**：基座版本、home 前缀、端口、归档 TTL。启动器**只读不写** | ⚠️ **只随附 `当前配置.toml.example`** —— 复制成 `当前配置.toml` 再改 |
| `版本信息说明/<version>.toml` | 每个基座要求 home 的 profile 具备哪些标记；**缺了直接拒绝启动** | ✅ 随附 `v0.1.7-rc.2` / `v0.2.0-rc.2` 两份**真名**文件（见下） |
| `密钥.env` | LLM 凭据（`KEY=VALUE` 一行一条，mode 600） | ❌ 不随附（凭据）。自己建，同样 mode 600 |
| `运行记录/` | 运行时自动创建：活实例日志、护栏输出、死后归档（TTL 默认 7 天） | 运行时生成 |

## ⚠️ 关于 `版本信息说明/<version>.toml`（最容易踩的一步）

启动器启动时会**断言**三处字符串逐字节相同：

```
启动器配置和日志/版本信息说明/<version>.toml     ← 文件名
原始代码研究/<version>/                          ← 检出目录名
启动器配置和日志/当前配置.toml 里的 version 值
```

⇒ 所以本仓**不把它改成 `.example`** —— 改名正是这套机制最容易错的一步。
随附的两份是你升到对应版本时真正用过的那两份（含 `[upstream]` 标签与 `[profile]`
要求的标记，以及历次迁移的记事）；**换版本请照 `v0.1.7-rc.2.toml` 的注释另写一份**，
文件名必须与你的检出目录名一致。

## 可选件（不在本仓）

- `tools/cloudflared-linux-amd64.staged`（约 38 MB）：`cloudflared` 不可执行时启动器会
  回落到它。**不入仓**（体积 + 可重下），自己放一份即可；没有也不影响启动。
