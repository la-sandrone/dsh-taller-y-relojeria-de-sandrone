# System Prompt 设计（五个使用场景）

> **这套设计的出发点**：流体静力平衡（$\frac{dP}{dr} = -\frac{G M(r) \rho(r)}{r^{2}}$）是**宇宙一切大型天体能够存在的最基本约束条件** —— 它不是天体的某项功能，而是让结构成立的前提；引力向内的自发起作用，压力梯度向外的恰好抵消，差一点就塌。
>
> **System Prompt 是同一件事**：它也不是"给模型加个功能"，而是让模型行为成立的条件。
> 那些约束条款本质上都是压力梯度项 —— 每一项都在抵消某一种特定的塌缩倾向。
>
> （这段话原本是本目录独立成仓时的**仓名** —— `equilibrio hidrostático`。并入本仓后名字没了，论点留下。）

本目录收录一套实际投产中的 **DeepSeek Harness（DSH）System Prompt 设计**，覆盖五个使用场景。

## 架构：公共区 + 分场景

五个场景共享一个**公共区**，各自再叠加场景特有的章节。这不是复用——是**约束的物理分层**（基础约束在所有场景下都成立，场景约束只在该场景的塌缩倾向上起作用）。

| 公共区章节 | 作用 |
|---|---|
| 环境信息和环境相关特殊说明 | 告诉模型它跑在什么环境里（WSL / 沙盒边界 / 不要自行装包） |
| 模型身份 | 每次装配时按实际路由插值，**禁止模型按记忆推断自己是什么模型** |
| 运行环境 | 会话 id / Harness 版本 / 沙盒 scratch 目录 —— 排查故障的第一手线索 |
| 角色定位 | 工作方式与代码质量取向 |
| 任务分类锚 | 动手前先判定任务类型（产出型 / 审查修订型），据此选风格 |
| 模型分治 | 按模型能力分治：某些引导只对特定模型有效，对另一个反而有害（有实测依据） |
| 计算外置铁律 | **禁止心算**，符号推导与精确数值一律交给工具 |
| 字符串里的中文引号用「」 | 代码字符串里的中文引号一律用 `「」`（`"` 是定界符，会破语法） |

**场景差异化**举例：编程版有「文件坐标系铁律」「庙算准则」「草稿纸准则」「主动回忆」；奇幻设定有「方法论工具箱」；硬科幻/学术/通用有「网络纪律」。

## 几条核心设计取向

**① 补的是系统性缺陷，不是知识**
每条准则都对应一次真实的失败。`八荣八耻` 从 13 条涨到 17 条，全是被实战咬出来的——不是"想到什么写什么"。

**② 约束外置**
模型不可靠的能力（算术、符号推导、精确计数、长程状态追踪）不靠自我约束，而是**交给外部工具与存储**。「计算外置铁律」「草稿纸准则」「文件坐标系铁律」都是这个思路的具体化。

**③ 承认模型会失败，并把失败写进 prompt**
例如明确指出「无外部反馈的自我纠错是负收益」——不期望模型"再想想就会对"，而是要求它**在特定信号出现时立刻停下发工具调用**。

**④ 分治而非普适**
「模型分治」一节记录了实测结论：某些引导锚对某个模型有效，对另一个**有害**。所以不做"一刀切的最优 prompt"，而是按模型分派。

**⑤ 约束的边界要被显式写出**
规则写得笼统 ≠ 规则生效。每条准则尽量给出**判据**（"这个引号会不会被解析器当定界符？"）而不是口号。

## 对话索引：上下文转接机制

长对话要换到新会话继续时，最朴素的做法是把记录整段贴过去。本体系改用**约定标记**，
把「让模型在几万行里找线索」这件**概率性**的事，降级为「精确字符串匹配」这件**确定性**的事。

**机制**：对话结束前生成索引（话题脉络 / 关键词速查表 / 近似入口点 / 关键决策表 / 产出物清单），
以 `# ░ 对话索引 ░` 起头附在导出文件末尾。新对话里只搜这一个标记，即可零歧义定位索引块，
再按关键词跳到需要的段落。

**标记字符的演化** —— 每一步都是被实际噪音逼出来的：

| 阶段 | 方案 | 问题 / 收获 |
|---|---|---|
| 1 | `# 对话索引` | "对话索引"四字在**讨论索引机制本身**时就会命中 —— 特异性不足 |
| 2 | 加 Markdown 标题标记 `#` | 实测零噪音，所有命中都是真正的索引块 |
| 3 | 叠加 Unicode block `█`（U+2588） | 特异性趋近于零 |
| 4 | **`█` → `░`（U+2591）** | ★ 见下 |

**第 4 步的判据值得单独记**：`█` 的**通用** IDF 已经很高，但对我不高，我写SCP基金会文档，`█` 正是制造「黑条涂黑」效果的高频字符。
换成几乎不承担语义功能的 `░` 之后，才真正接近零互信息。

> **教训**：标记字符的选择不能只看「在一般语料里罕见吗」，还要看
> 「**在这个使用者自己的语料里罕见吗**」—— IDF 是相对于语料测的，而语料因人而异。

这个思路和「计算外置铁律」是同一个：**模型不擅长的部分交给确定性机制，
模型只负责需要判断的部分。**

## 相关研究与实践

完整综述（**110 条参考文献**，含证据分级与检索缺口声明）在本仓 [`docs/RESEARCH.md`](../docs/RESEARCH.md)。
覆盖六个方向：system prompt 有效性 / 约束机制类型学 / 负面结果证据 / 指令冲突与优先级 /
工具调用激励 / 工业经验 vs 研究验证。

**几条最值得一读的**：

- **无外部反馈的自我纠错是负收益** —— 有外部反馈的反思才有效。本体系的「计算外置铁律」
  与「中断语：写到这里就停」正好踩在这个边界上。
- **指令密度到 500 条时，最强前沿模型只有 68% 遵循率**，且存在对**靠前指令**的系统性偏置。
  （本体系最长的场景是 21 个章节 —— 越靠后的章节实际遵守率值得自查。）
- **`Control Illusion`（AAAI-26）**：system / user 的分离**建立不起可靠层级**，
  而**社会层级框架**（权威、专业性、共识）的影响力反而强于角色划分。
- **★ OpenAI 相隔约一年实质撤回自己的建议** —— 2024 指南把「显式要求模型一步步思考」
  列为六大策略之一，而 GPT-5 世代指南已转向 reasoning effort 内化（Google 同向提示：
  用 Thinking 模式时试试**不要**显式写逐步推理指令）。**同厂商推翻自己**的一手案例，
  比引用任何一条论文都更能说明「提示技术会随版本过时」。
- **三家厂商一致推荐 persona，而系统评测不支持它提升客观任务表现** ——
  "三家一致"在这里**不构成证据**，它们共享的是实践者直觉，不是对照实验。

每条论断的引用、逐条证据分级（✅有研究支撑 / ⚠️经验之谈 / ❌与研究冲突）、
以及**检索缺口声明**（7 条，其中 3 条落在本体系上、已转成自测建议）均在 `docs/RESEARCH.md`。

## 用法

这些 prompt 是为 **DSH** 写的（含 `{{cwd}}` 等 DSH 模板变量、以及对 DSH 专属工具名的引用）。
**直接拿去用在别处会有大量悬空引用**，但设计取向与约束手法可移植。

若要参考，建议按需取章节，而不是整份复制——尤其「环境信息」「模型身份」「运行环境」三节是环境强绑定的。
